# 候选问题：用跨模型复现做 harness 失败归因

> **来源**：基于 ECDYSIS（arXiv:2609.11677v2）与 HarnessCompass（arXiv:2608.01918）的研究空白分析；分层架构部分参考 SSA（*Dissecting model behavior through agent trajectories*，arXiv:2606.17454）。
> **标注约定**：
> - "p.X"：指 ECDYSIS 原文页码。
> - 【假设】：原文没有做过、属于本问题要回答的反事实推测。
> - 【推断】：基于原文事实的个人判断，原文未明确说明。

---

## 一、问题陈述

> 在失败驱动的 harness 演化中，能否用**同一失败在不同模型上是否复现**作为可自动计算的证据，在修改 harness **之前**区分 harness 缺陷（HLR）和演化模型自身的局限（MSA），从而在不依赖人工审计、也不依赖模型自我归因的前提下，提升演化出的 harness 在其他模型上的效果？

**最终目的**：让演化出的 harness 在**未参与演化的模型**上也表现好（跨模型泛化）。区分 MSA 和 HLR 只是手段：区分的结果用来决定**每条修改以什么范围、什么形式生效**（见第七节），而不是简单地删掉 MSA。

**表述上的注意点**：

1. 跨模型一致性只能**作为证据**提升归因的准确性，不能直接**等同于**归因。"多个模型都失败就是 HLR，只有一个模型失败就是 MSA"这种二分规则存在反例，见第三节案例 B。
2. MSA 不等于有害。ECDYSIS 承认 MSA 也可能有效且可跨任务复用（p.14）；它自己的数据也显示，w/o FDCR 的 MSA 比例（75.61%）高于 SE（60.00%），但跨模型平均准确率（64.56%）也高于 SE（58.67%）（p.7 Table 1；p.20 Table 10）。因此 MSA 比例 t 应作为**诊断指标**，而非优化目标。

## 二、场景

**典型使用方式**：用一个便宜的模型把 harness 演化好，冻结后部署到多个模型上。

| 论文 | 演化用的模型 | 迁移到的模型 |
|---|---|---|
| ECDYSIS | 仅 Qwen3-8B（p.16，Appendix C） | Qwen3-14B、Qwen3-32B、MiniMax-M2.7、Llama-3.1-8B |
| HarnessCompass | 仅 GPT-5.4 | Claude-Sonnet-4.6 |

**矛盾**：演化时看到的每一个失败都**只来自一个模型**，但演化出的 harness 要服务**多个模型**。一个失败究竟是 harness 的问题，还是这个模型自己的问题，单靠演化模型本身的数据很难判断。

## 三、案例

ECDYSIS 附录中的三个真实案例分别对应三种情况。

| | 案例 A：Retail 退款（p.14） | 案例 B：Airline 空操作写入（p.14–15） | 案例 C：Retail 取消订单（p.14） |
|---|---|---|---|
| **实际发生了什么** | 用户没指定退款去向，模型选了礼品卡；正确答案是原支付方式 | 模型用"写"操作来查询预订，提交的行李数和当前值相同，产生了一条多余的支付记录，导致后续退款计算出错 | 提示词说"修改过的订单仍可取消"，但取消工具实际会拒绝这类请求 |
| **harness 怎么改的** | 全局禁止退到原支付方式以外的任何地方 | 新增规则：拦截"写入值与当前值相同"的空操作写入 | 让提示词与工具的实际行为保持一致 |
| **人工审计结论** | **MSA** | **HLR** | **HLR** |
| **其他模型会怎样【假设】** | 如果别的模型会询问用户或默认退回原支付方式 → 只有一个模型失败，可判定为 MSA，**不应设全局禁令** ✓ | 更强的模型可能根本不会用"写"去"读" → **只有一个模型失败，但这确实是 harness 缺陷** ✗ | 提示词本身在误导，所有模型都可能上当 → 多个模型一致失败，可判定为 HLR ✓ |

### 案例 B 说明二分规则的问题

有些 harness 缺陷只有能力较弱的模型才会触发。harness 没有挡住空操作写入带来的副作用，这确实是缺陷，但强模型绕开了它。如果简单地把"只有一个模型失败"判为 MSA，这类真实存在的缺陷就会被漏掉。

因此，跨模型信号需要和**修改的性质**结合起来看：

- 案例 A 的修改是**删减合法动作**（去掉政策允许的礼品卡选项）；
- 案例 B 的修改是**拦截有害的副作用**（多余的支付记录）。

### 2×2 分析框架

| | 跨模型一致失败 | 只有演化模型失败 |
|---|---|---|
| **HLR** | 案例 C：容易判断 | **案例 B：危险象限，会被漏判** |
| **MSA** | 多个模型共有的弱点，或任务本身有歧义【假设】 | 案例 A：容易判断 |

这个框架本身可以作为论文的一个分析贡献。

## 四、现有工作遗漏了什么

| 遗漏 | ECDYSIS | HarnessCompass |
|---|---|---|
| **归因用的信号来源** | 跨任务复发。但这个信号来自**同一个模型**，模型自身的弱点同样会跨任务复发；作者承认复发 "insufficient for reliably distinguishing recurring model limitations from harness deficiencies"（p.2 第 5 段） | 由**刚刚失败的那个模型**自己报告失败原因（harness / 自身推理 / 任务歧义 / 环境）。论文没有用人工标签验证过这种自我归因的准确率【基于正文；附录 C 未读】 |
| **归因发生在什么时候** | 方法运行时**不归因**；MSA 比例只能事后由人工审计（审计者为作者，p.10）统计，无法在训练过程中使用 | 在演化过程中归因，但依赖模型自报 |
| **其他模型的作用** | 只在**最终评估**时作为测试对象 | 同左 |

**核心遗漏一**：两篇论文手里都有多个模型，但只把它们用在了"考试"上，没有用在"诊断"上。跨模型信息的唯一用途是事后证明泛化效果，没有在演化过程中帮助判断失败原因。

### 两篇论文区分之后是怎么处理的

| | ECDYSIS | HarnessCompass |
|---|---|---|
| 运行时是否区分 | **否**。人工审计的 MSA/HLR 标签只用于事后统计 t（p.14） | **是**。由失败的模型把失败归到 harness / 自身推理 / 任务歧义 / 环境四类之一 |
| 对模型局限类失败的处理 | 不单独处理，只靠证据分级来降低其影响：覆盖至少两个任务的失败组优先，单任务组作为辅助证据（p.5）；失败组是诊断证据而非必须修复的目标（p.5）；Critic 检查触发条件过宽、误拦合法行为，Moderator 避免不必要的修改（p.5）。MSA 是"缓解而非禁止"，有复发证据支持时会被保留（p.3） | 归因为非 harness 原因的反馈**可以丢弃**（据附录 prompt）；归因为 harness 的反馈经轨迹核实后，作为补充证据，修改仍需通过泛化闸门。对"自身推理"类失败是否设计专门的引导性修改，**未见说明**【基于正文；附录 C 未读】 |
| 修改的生效范围 | 一律**全局** | 一律**全局** |

**核心遗漏二**：两篇论文对每条修改都只有两种选择，**全局修改或者不修改**。缺少第三种选择：**修改，但限定作用范围或换一种形式**。

### 已有工作：SSA 提出了分层，但没有划分标准

SSA（Simple Strands Agent，arXiv:2606.17454，AWS AI Labs）已经采用了"共享核心 + 按模型家族的适配器"结构，是"限定作用范围"这一选项的已有实践：

| 层 | 内容 | 原文依据 |
|---|---|---|
| **共享核心** | 事件循环（调用模型 → 执行工具 → 追加结果 → 重复）、反馈语义、评估协议 | Appendix A："The event loop is the same across all models." |
| **按家族的适配器** | 工具调用引导（Claude 适合量化目标，Gemini / Grok 适合定性方向）；工具接口选择（GPT 用 `apply_patch`；Grok 拆分编辑工具、关闭行号显示） | §2.2、§2.3、图 1；§4.2："only the narrow interface adapters" differing |

SSA 还提出了 **intent-execution gap（意图与执行之间的落差）**：harness 没有忠实执行模型的意图（如只想改一处却改了所有匹配处），或模型没有得到环境的准确反馈（如 shell 输出截断掩盖了测试失败）。这与 ECDYSIS 对 HLR 的定义（解析、接口语义、反馈呈现方面的错误，p.14）基本一致。

**SSA 没做全的地方**：

| 维度 | SSA 的做法 | 缺了什么 |
|---|---|---|
| 组件怎么得到 | **人工设计**，作者反复试提示词，发现没有通用的"黄金提示"（§2.2） | 没有放进失败驱动的自动演化中 |
| 核心与适配器怎么划分 | 作者凭经验判断 | **没有划分标准**；intent-execution gap 没有正式的诊断流程或度量指标 |
| 适配粒度 | 模型**家族**级别 | 无法区分同家族不同大小的模型 |
| 适配内容 | 只涉及提示和工具接口 | 没有涉及**约束和动作拦截**类修改（如 ECDYSIS 退款案例这种删减合法动作的 MSA） |
| 适配器效果 | 只有定性描述，**没有消融** | 不知道哪个适配器真的有用 |
| 跨模型伤害 | 只有零散观察（给 Gemini / Grok 用量化提示时常出现空工具调用）；提到风险但**未系统测试** | 没有测量适配器对其他模型的影响 |
| 新模型 | 未讨论 | 没见过的模型该用什么适配器 |
| 领域 | 代码类基准（SWE-Bench-Verified / Pro、Terminal-Bench-2、Deep-SWE） | 没有覆盖 τ²-Bench 这类有状态、有业务政策约束的环境 |

【以上 SSA 内容来自 arXiv HTML 正文经抓取工具整理的摘要与截断摘录；附录 "Limitations of the solution-distance metric" 未读。正式引用前需对照原文核实。】

**核心遗漏三**：SSA 回答了"**应该分层**"，但没有回答"**每条修改该放哪一层、由谁决定、依据什么**"。

## 五、后果

1. **迁移到其他模型时，成绩可能比初始 harness 还差**。ECDYSIS Table 6（p.18）中，SE 在 τ²-Airline 上：

   | 模型（均未参与演化） | 初始 harness（Human-Aug.） | SE 演化后 |
   |---|---|---|
   | Qwen3-14B | 38.33% | **23.33%** |
   | MiniMax-M2.7 | 81.67% | **73.33%** |

   论文没有把这种退步归因到具体的修改上，但这正是 MSA 导致 harness 与演化模型耦合时预期会出现的现象【推断】。

2. **合法的动作空间被缩小**。案例 A 中，一个模型的局部错误被固化成了全局禁令，导致政策允许的礼品卡退款对**所有**模型都不可用（p.14）。

3. **聚合反而放大问题**。只做跨任务聚合时，MSA 比例从 60.00% 升到 75.61%（p.20 Table 10）。复发信号越强，单一模型的弱点越容易被当成 harness 缺陷。

4. **过程无法监控**。MSA 比例只能事后人工统计，训练过程中没法知道 harness 是否正在向演化模型的弱点倾斜，也就没法据此及时停止或回滚。

5. **补救成本高**。ECDYSIS 用 FDCR 把 MSA 比例压回 45.45%，代价是额外的演化成本：τ²-Retail 上的 API 成本从 $2.485 增加到 $5.763（p.20 Table 9）。而且 FDCR 依然没有使用任何来自其他模型的信息。

## 六、形式化

- **输入**：
  - 初始 harness H；
  - 演化模型 m₀；
  - 参照模型集合 M = {m₁, …, m_k}（便宜，且尽量来自不同模型家族）；
  - 训练任务集 D。
- **证据**：对演化模型 m₀ 的一个失败 f，收集：
  1. 参照模型在同一任务上是否复现失败、在哪一步失败；
  2. 失败在不同任务间是否复发（沿用 ECDYSIS 的信号）；
  3. 对应的修改是否会**删减环境策略允许的动作**（针对案例 A 的特征）。
- **输出**：
  1. 每个失败组属于 HLR 的概率估计；
  2. 据此为对应修改选定**生效范围**（全局 / 模型专属）和**形式**（限制动作 / 补充引导），见第七节。
- **目标**：在演化预算受限的条件下，最大化演化出的 harness 在**未参与演化的模型**上的留出成绩。
- **诊断指标（不作为优化目标）**：MSA 比例 t、修改导致的合法动作空间缩小程度、推理 token 开销。

## 七、区分之后的处理策略

一条修改对其他模型有没有伤害，主要取决于两点：

1. 它是否**缩小了合法动作空间**；
2. 它是否**被强制施加到所有模型上**。

区分 MSA 和 HLR 的价值，在于为这两个决策提供依据：

| 归因结果 | 建议的处理 | 理由 |
|---|---|---|
| **HLR**（跨模型一致失败，例如案例 C） | 作为**全局**的持久修改，对所有模型生效 | 修复的是机制本身，对哪个模型都有益 |
| **HLR，但只有弱模型会触发**（危险象限，例如案例 B） | 仍然**全局保留** | 拦截空操作写入这类修改只阻止有害的副作用，强模型本来就不会触发，因此不会受损 |
| **MSA，且修改是删减动作**（例如案例 A） | **不做成全局禁令**，二选一：① **换形式**，例如把"禁止退到礼品卡"改为"用户没指定时先询问"；② **限范围**，只在演化模型上启用 | 全局禁令会让所有模型失去合法选项，这正是迁移后成绩退步的可能来源【推断】 |
| **MSA，且修改是补充引导**（例如加提示、加恢复步骤） | 可以保留，但需要**更强的证据**才接受 | 不缩小动作空间，对其他模型伤害较小，但会增加 token 开销 |

### 落地架构：通用核心 + 模型专属适配层（借鉴 SSA）

- **HLR** 进入通用核心，对所有模型生效；
- **MSA** 进入模型专属适配层，只对需要它的模型启用。

这样 MSA 不必丢弃，也不会污染其他模型；对没有适配层的新模型，最差情况是只用核心，相当于完全共享方案。

**定位**：分层结构本身**不是本问题的贡献**，SSA 已经提出并实践过（见第四节）。本问题的贡献是**为分层提供自动的、有证据支撑的路由机制**：

| SSA 没做 | 本问题要做 |
|---|---|
| 人工划分，没有标准 | 用**跨模型复发 + 修改性质**作为证据，自动决定修改进入核心还是适配层 |
| 静态设计 | 嵌入**失败驱动的演化过程**，演化中产生的修改自动路由到对应的层 |
| intent-execution gap 没有诊断方法 | 跨模型一致失败可作为 gap 的**可计算信号**：多个模型都"意图正确但执行出错"，很可能就是 gap【推断】 |
| 没有测量跨模型伤害 | 系统测量适配层对其他模型的影响（RQ5、RQ6） |
| 只覆盖提示和接口，家族级粒度 | 覆盖**删减动作**类修改，粒度可到单个模型，并在 τ²-Bench 这类有业务政策约束的环境中验证 |

**可以直接借用 SSA 的地方**：
- 核心 / 适配器的工程划分（事件循环、反馈语义作核心；提示、接口作适配器）；
- intent-execution gap 概念，可作为 HLR 的一个具体子类，增强划分标准的依据；
- SSA 已给出"适配器确实必要"的证据，本问题无需再论证分层的必要性。

### 三方对比

| | ECDYSIS | HarnessCompass | SSA | 本问题 |
|---|---|---|---|---|
| 是否自动演化 | 是 | 是 | 否（人工设计） | 是 |
| 运行时是否区分模型局限 / harness 缺陷 | 否 | 是（模型自我归因） | 否（作者经验判断） | 是（跨模型证据 + 修改性质） |
| 对模型局限类修改的处理 | 降低权重，有证据就保留 | 丢弃 | 放进家族适配器 | 按**范围和形式**处理，自动路由 |
| 修改的生效范围 | 一律全局 | 一律全局 | 核心 / 家族适配器 | 核心 / 模型专属适配层 |
| 是否测量跨模型伤害 | 否（只测迁移成绩） | 否（只测迁移成绩） | 否 | 是 |

### 风险

| 风险 | 说明 |
|---|---|
| 路由错误 | 把案例 B 那类"只有弱模型会触发的 HLR"错放进适配层，其他模型就失去保护；分层效果完全取决于归因质量 |
| 适配层也需要数据 | 每个模型的适配层都要用该模型跑一遍演化，成本需与"整套重新优化"（Better Harnesses, Smaller Models，arXiv:2607.08938）比较 |
| 层间冲突 | 适配层规则可能与核心冲突（如核心允许礼品卡退款，适配层禁止），需定义优先级 |
| 新模型 | 只用核心，还是借用"最相近模型"的适配层？ |

## 八、子问题与假设

| 编号 | 子问题 | 可检验的假设 |
|---|---|---|
| RQ1 | 跨模型一致性对 HLR/MSA 的区分能力有多强？ | 与人工标签相比，"跨模型一致性 + 跨任务复发"组合的归因准确率高于单独使用跨任务复发 |
| RQ2 | 案例 B 那类"只有弱模型触发的 HLR"占多大比例？能否通过修改性质（拦截副作用 vs. 删减动作）区分出来？ | 加入"动作空间是否缩小"这一特征后，危险象限的漏判率下降 |
| RQ3 | 需要多少个参照模型、用多便宜的模型才划算？同家族模型的效果会下降多少？ | 一个来自不同家族的小模型就能拿到大部分收益；同家族模型（如 Qwen3-8B 和 Qwen3-14B）提供的信息更少 |
| RQ4 | 用这个归因信号引导演化，最终效果如何？ | 在**未参与演化的模型**上，成绩高于 ECDYSIS（w/ FDCR），且成本与 FDCR 相当或更低 |
| RQ5 | 区分之后，按**范围和形式**处理 MSA，与直接丢弃 MSA（HarnessCompass 式）、或一律全局保留（ECDYSIS 式）相比，哪种效果更好？ | 按范围和形式处理时，演化模型上的成绩接近"全局保留"，未参与演化的模型上的成绩不低于"直接丢弃" |
| RQ6 | 自动路由（本问题）与人工划分（SSA 式）相比，划分结果是否一致？适配层对其他模型的伤害有多大？ | 自动路由在未参与演化的模型上不劣于人工划分；被路由进适配层的修改，若强行全局施加，会降低其他模型的成绩 |

## 九、需要提前确认的事项

| 事项 | 说明 |
|---|---|
| **ground truth 怎么来** | ECDYSIS 的人工标签是按"**修改决策**"标的，不是按"**失败**"标的。需要把失败映射到对应的修改，或者用 p.14 的审计协议自己重新标注。ECDYSIS 是否在 GitHub 仓库（https://github.com/cuiyu-ai/Ecdysis ，p.1）中公开了审计标签，原文未说明，需要去仓库确认 |
| **任务本身的问题** | 所有模型都失败，也可能是任务描述有歧义或标准答案有误，而不是 harness 有缺陷。可以借鉴 HarnessCompass 四类归因中的"任务歧义"和"环境" |
| **模型间失败相关** | 同家族模型（如 Qwen 系列）可能共享训练数据，失败会相关。应选不同家族的模型，或在方法中显式建模这种相关性（可与"复发作为证据的可识别性"理论方向结合） |
| **额外成本** | 参照模型需要多跑一遍训练任务。要和 FDCR 的成本放在同一张表里比较，否则收益可能被质疑只是用更多计算换来的 |
| **SSA 原文核实** | 第四、七节关于 SSA 的引文来自抓取工具的摘要与截断摘录，需对照 arXiv:2606.17454 原文核实段落与措辞；附录中 solution-distance 指标的局限一节尚未阅读 |

## 十、最小可行实验

- **设置**：在 τ²-Airline 上，让 Qwen3-8B（演化模型）和 Llama-3.1-8B（不同家族的参照模型）在 ECDYSIS 的初始 harness（Human-Aug.）下各跑一遍训练任务。
- **要看的结果**：
  1. 两个模型失败的重叠程度；
  2. 按 p.14 的审计协议标注后，2×2 框架中每个象限各有多少失败；
  3. 重叠的失败与不重叠的失败，分别更接近 HLR 还是 MSA。
- **继续做下去的条件**：两类失败在 HLR/MSA 上的区分明显，并且危险象限（只有演化模型失败但属于 HLR）所占比例不至于让跨模型信号失效。
