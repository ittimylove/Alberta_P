## 问题 1：模型升级时，用旧模型当 meta-agent 会不会更好？

### 1.1 一句话问题

在模型升级的场景下，task agent 从旧模型换成新模型。此时用**旧模型**担任 meta-agent，它当初参与过 harness 的设计，熟悉这套 harness 和这些任务，演化效果会不会比用 frontier 模型担任 meta-agent 更好，同时成本更低？

### 1.2 直觉：高考老师的类比

一位高考老师的个人能力未必很强，但他能教出很厉害的学生。原因是他见过大量适合高考的题目，知道怎么答才能得高分。

放到 HarnessX 里：
- **老师** = 旧模型（meta-agent）。原本的 harness 是为它适配的，它“知道这套 harness 和这些任务怎么才能拿分”。
- **学生** = 新模型（task agent）。能力更强，但还没在这套 harness 和这些任务上“训练”过。
- **问题**：老师的“应试经验”能否弥补他能力上的不足，教出比 frontier 老师更好的学生？

### 1.3 现有工作的空白

| 现状 | 原文依据 |
|---|---|
| 所有实验的 meta-agent 都固定为 Claude Opus 4.6，属于 frontier 模型 | p.15 §6.1 *Models* 段；p.29 附录 A.4 |
| 作者明确表示没有评估较弱的 meta-agent 能否达到相当的提升 | p.22 §7.4 第 2 段：“we do not evaluate whether a weaker meta-agent can achieve comparable gains” |
| meta-agent 的能力要求被列为局限；开源模型能否胜任 meta-agent 尚未测试 | p.23 §7.7 *Closed-source meta-agent* |
| 四阶段架构对准确率没有帮助，这个结论只在 “this meta-agent capability level” 下成立 | p.18 §6.4 |
| 论文把“换模型版本就要重新定制 harness”列为核心痛点，但实验中没有模拟“模型升级”的场景 | p.3 §1 第 2 段 |
| 跨家族的结果：提升幅度跟随 task agent 的起点高低，与 meta-agent 是否同家族无关 | p.17 §6.2 *Cross-model generalization* 段；p.22 §7.4 |

**空白**：没有任何实验改变 meta-agent 的能力，也没有任何实验模拟“旧 harness + 新 task agent”的升级场景。

### 1.4 需要先澄清的两点

**(a) harness 最终适配谁？**
【推断】在 AEGIS 中，meta-agent 读的是 task agent 的轨迹，门控看的是 task agent 的成绩（p.9 算法 1 第 5–7 行、第 22 行）。所以无论老师是谁，演化出来的 harness 都是针对学生（新模型）优化的。

这和高考类比是一致的：老师怎么教，最终由学生的考试成绩来检验。所以本问题的焦点不在于“harness 适配谁”，而在于**谁当老师，能更快、更省、更稳地把学生教好**。

**(b) 老师的“应试经验”从哪里来？**
这一点必须拆开，否则实验结论无法解释：

| 经验来源 | 含义 | 在 HarnessX 中对应什么 |
|---|---|---|
| **模型本身** | 旧模型对这类任务的“直觉”：它自己作为 task agent 时是怎么失败、怎么被修好的 | 旧模型的参数（如果它曾是 task agent） |
| **演化历史** | 上一次演化留下的记录：哪些修改有效、哪些失败、哪些任务一直解决不了 | 运行目录里的 journal.md、ship_outcomes.json、task_history.jsonl、rejected_candidates.jsonl（p.43 附录 E.1） |

【推断】第二种经验存在文件里，任何 meta-agent 都能读到。如果旧老师的优势只来自演化历史，那么让 frontier 老师也读这份历史，可能就能获得同样的好处。

### 1.5 假设

- **H1（主假设）**：在模型升级场景下，以旧 harness 为起点，旧模型作为 meta-agent 的演化效果不低于 frontier meta-agent，并且总成本更低。
- **H1a（经验来自模型）**：即使不给演化历史，旧模型 meta-agent 也优于“没有历史的 frontier meta-agent”。
- **H1b（经验来自历史）**：旧 meta-agent 的优势主要来自演化历史；frontier meta-agent 读了同样的历史之后，优势消失。
- **H0（对立假设）**：meta-agent 的能力才是瓶颈。弱老师难以诊断强学生的失败，写不出能跑通的工具或 processor 代码，也难以识别 reward hacking。结果是被拒绝的候选更多、所需轮次更多，最终效果更差，总成本也未必更低。

### 1.6 实验设计

**升级场景的构造**
1. **阶段 0**：task agent = 旧模型，从 H₀ 开始演化，得到 H_old，并保存完整的运行目录（演化历史）。
2. **阶段 1**：task agent 换成新模型，在以下几种条件下继续演化。

**实验条件**（核心是一个 2×2 设计：meta-agent 新旧 × 有无演化历史）

| 条件 | meta-agent | 起点 harness | 是否提供阶段 0 的演化历史 | 作用 |
|---|---|---|---|---|
| E0 | —（不演化） | H_old | — | 基线：旧 harness 直接给新模型用 |
| E1 | —（不演化） | H₀ | — | 基线：判断 H_old 对新模型是有帮助还是有害 |
| **A** | frontier | H_old | 否 | 论文的默认做法 |
| **B** | 旧模型 | H_old | 否 | 检验 H1a |
| **C** | 旧模型 | H_old | 是 | 高考老师的完整版本 |
| **D** | frontier | H_old | 是 | 检验 H1b |
| F（可选） | frontier | H₀ | 否 | 判断从头演化是否反而更好 |
| G（可选） | 按阶段混用：Digester 用旧模型，Evolver 和 Critic 用 frontier | H_old | 是 | 成本折中方案 |

**控制变量**
- 新旧模型最好来自**同一家族的前后两代**，避免把“家族差异”混进“新旧差异”。
- 所有条件使用相同的 meta-agent token 预算或相同的总成本上限，二选一，事先固定。
- 题目集、轮数上限、提前停止规则、pass@2 都与论文保持一致（p.15 §6.1；p.29 表 8）。

**基准的选择**
- **ALFWorld**：收敛快，修改以提示词为主（p.39 附录 D.2）。对弱老师相对友好。
- **SWE-bench Verified 或 GAIA**：需要写工具或代码类的修改（p.36 附录 C.1；p.42 附录 D.5）。对弱老师是压力测试。

两类基准对比，可以检验“学生越强，越只需要改提示词，因此弱老师也够用”这一子假设。

**指标**

| 指标 | 用途 |
|---|---|
| 峰值和终值的 pass@2 | 效果；终值反映稳定性 |
| **留出测试集上的成绩** | 论文没有做这一项（p.23 §7.7），这里补上，防止过拟合到演化题集 |
| 收敛所需轮数 | 效率 |
| 门控拒绝率、manifest 命中率 | 老师给出的修改质量（定义见 p.20 §6.6、p.37 附录 D） |
| 检出的 reward hacking 和退化案例 | 老师能否识破学生钻空子 |
| **meta-agent 成本与 task agent 运行成本分开统计** | 判断总成本是否真的更低；论文的 token 统计没有拆分这两项 |

**重复次数**：每个条件至少重复 3 次，报告均值和方差（论文没有报告多次运行之间的方差）。

### 1.7 结果怎么解读

| 观察到的结果 | 说明 |
|---|---|
| B ≥ A | 支持 H1a：熟悉这套 harness 的旧模型本身就是好老师 |
| C > B，且 D ≈ C | 支持 H1b：优势来自演化历史，不来自旧模型本身；用 frontier 加历史就够了 |
| C > D | 旧模型的经验无法完全用文件传递，“老师见过的题”确实在参数里 |
| B、C 都明显低于 A | 支持 H0：meta-agent 的能力才是瓶颈 |
| 在 ALFWorld 上 C ≈ A，在 SWE-bench 上 C 明显低于 A | 弱老师只在“改提示词”的场景中够用 |
| E0 < E1 | 旧 harness 对新模型反而有害，升级时应该重新从 H₀ 开始 |

### 1.8 风险与需要注意的问题

- 【推断】**弱老师可能诊断不了强学生**。新模型的失败方式可能超出旧模型的理解范围。
- 【推断】**代码能力的门槛**。Evolver 必须实际运行新代码，并做 Level-2 验证；依赖的包和 API 必须先确认存在（p.31–32 附录 B.1）。旧模型可能达不到这个要求。
- 【推断】**上下文长度**。GAIA 一轮约产生 10M token 的原始轨迹（p.10）。旧模型的上下文窗口较短，会更依赖 Digester 的压缩。
- 【推断】**知识截止时间**。旧模型可能不知道新的 API 和工具，容易提出过时或幻觉出来的修改。
- **成本可能被抵消**。弱老师如果导致更多轮次，每一轮新模型（task agent）都要把全部题目跑一遍，省下的 meta-agent 费用可能被抵消。参考 p.18 §6.4：单 agent evolver 正是因为候选被拒绝得多而多花了 14% 的 token。
- **可行性**。较老的模型可能已经下线或无法稳定调用，需要提前确认。
