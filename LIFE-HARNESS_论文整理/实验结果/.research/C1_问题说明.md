# C1　模型升级后，旧 harness 的哪几层失配、为什么失配

> 2026-10-19　｜　标注：**[核实]** 已回到 PDF 原文核对　**[摘要]** 只读了摘要，未读正文　**[笔记]** 来自本地精读笔记，未回到原文核对　**[判断]** 根据证据推理，尚不确定　**[假设]** 待实验检验

## 问题定义

为旧模型 M 调好一套 7 层 harness H（system prompt、tool description、tool implementation、middleware、skill、sub-agent、long-term memory），连同它的操作点 θ（步数预算、超时）。现在换成同一家族的新模型 M′，H 原样沿用。

- 定义第 l 层的贡献为 δₗ(M) = acc(H, M) − acc(H 去掉第 l 层, M)。
- 如果 δₗ(M′) 明显小于 δₗ(M)，甚至变为负值，就说第 l 层**失配**。

**研究问题**：失配集中在哪几层？每一层是由四种机制中的哪一种造成的？只针对失配的层做修改，能否挽回大部分损失？

四种机制：
1. **冗余**：这层的作用已被新模型的能力吸收；
2. **接口失配**：这层的接口与新模型的习惯对不上；
3. **层间冲突**：几层叠加后互相干扰；
4. **操作点**：θ 不再适合 M′。

## 场景：为什么选这个问题

每次模型升级都会遇到这个问题。AHE、Self-Harness、SSA 都把"换模型后 harness 需要重新适配"当作研究动机 [核实]，但本地 8 篇论文里没有一篇做过同家族"旧 harness + 新模型"的实验 [核实]。

现在升级时只有两种做法：
- **整体沿用**：理由是迁移结果为正；
- **整体重跑演化**：AHE 一轮约 32 小时 [笔记]；HarnessX 的 meta-agent 一次要用 100M–175M token [笔记]。

两种做法都回答不了"旧 harness 错在哪里"。所以选这个问题，不是因为想用逐层消融这个方法，而是因为升级时要做的决策（删层、改接口、拆开冲突、只改操作点）依赖这个答案，而这个答案目前没有人测过。

## 缺口：现有工作漏掉了什么，为什么会改变结果

1. **参照点不对。** 现有迁移实验都是拿演化后的 harness 和种子 harness 比，"比种子好"不等于"没有失配"。
   - 例：HarnessFix 修好的 harness 用在源模型上 +18.4，迁移到其他模型只有 +5.5~+9.5 [核实]。中间丢掉的 9~13 个点就是迁移的代价，论文只报告了"仍为正"。
2. **只看整体，各层的抵消被掩盖。**
   - AHE 在同一个模型上已经出现层间抵消：三个单组件增益合计 +11.1 pp，完整版只有 +7.3 pp；单独加入 system prompt 是 −2.3 pp；Hard 档上只加 memory 是 63.3%，完整版只有 53.3% [核实]。
   - 换模型后，"整体为正"可能是"几层在帮忙、几层在拖后腿"相加的结果 [判断]。
3. **操作点与 harness 内容混在一起。** AHE 自己承认，跨模型迁移的数字"conflate harness portability with operating-point coupling"，同家族内的增益也不单调（medium +2.3，high +7.3，xhigh +2.3）[核实]。

**这些遗漏为什么会改变结果**：如果 C1 测出某几层在 M′ 上作用反号，那么 LIFE"与模型无关"、AHE 和 HarnessFix"迁移为正"这些结论就要改写为"整体为正，但掩盖了反号的层" [假设]。升级的做法也会随之改变：从整体重跑，变成只修一两层或只改操作点。由于演化循环倾向于往 harness 里加东西（AHE 的 tool 长到 1364 行 [笔记]），C1 还可能指出正确的做法是删层 [假设]。

## 最强反例，以及现有方法能否直接解决

| 反例或替代方案 | 力度 | 回应 |
|---|---|---|
| **迁移普遍为正，失配可能很小**：LIFE 在 126 个设置中提升了 116 个 [笔记]；AHE 换到 5 个基座，增益全为正 [核实] | 最强 | 这些都是跨家族迁移，或者从弱模型往外迁移，不是同家族升级；LIFE 只覆盖确定性环境。它削弱了 C1，但没有回答 C1 |
| **增益缩水只是天花板效应**：更强的模型从 harness 中获益更少（2605.30621）[摘要] | 必须排除 | 用轨迹区分：该层被调用了但出现接口报错，是失配；该层几乎不被调用或调用后行为不变，是冗余 |
| **直接在 M′ 上跑 Self-Harness 或 AHE** | 工程上可行 | 能得到一套新 harness，但给不出分层归因，下次升级还得从头再来。C1 的结果反过来可以作为这些方法的廉价基线："旧 harness + 只修失配层" |
| **只重调操作点就够了** | 可能成立 | 设计里专门留了一个条件来检验这一点。如果成立，题目缩小为"操作点混杂"，这本身就修正了 AHE 迁移结论的解读 |
| **已有工作可能已经做过**：2609.20804 比较了 3 个 harness 因素 × 4 个模型；2610.00917 比较了 66 个模型 × harness 配置，模型排名会翻转 [摘要] | 未知 | 两篇的摘要里都没有同家族新旧模型的比较，也没有 7 层级别的消融，但正文还没读 |

## 最小验证，以及继续、调整或放弃的依据

**第 0 步（1 天）**：读完 2609.20804 和 2610.00917 的正文，确认同家族 M 和 M′ 两代模型都能调用，并查好价格。
- 正文里已经有同家族的新旧对比，并做了组件级分析 → **放弃**，或者把题目调整为"扩展到 7 层"。

**第 1 步（约 2 周）**：
1. 从 SWE-bench Verified 抽 20 题。
2. **先在 M 上把 H 调好**。这一步不能省，否则就不存在"旧 harness"。
3. 跑 4 组条件，每题 k=3：
   - M 上：H、种子 H₀；
   - M′ 上：H、H₀、H 加上按 M′ 重设的操作点。
4. 计算 G(M) = acc(H, M) − acc(H₀, M) 和 G(M′)，并估计运行之间的标准差 σ。

**判断规则**：

| 结果 | 结论 | 决策 |
|---|---|---|
| G(M′) 比 G(M) 低 2σ 以上，且重设操作点后挽回不到一半 | 失配存在，并且来自 harness 内容 | **继续**：逐层去掉 7 层，再加种子，共 9 个配置；轨迹按四种机制归类；只对嫌疑层对补做两两交互 |
| 重设操作点后挽回一半以上 | 失配主要来自操作点 | **调整**：题目缩小为"操作点混杂" |
| G(M′) 与 G(M) 的差在 2σ 以内 | 反例成立，或者噪声太大 | 用更难、更有区分度的子集再试一次；仍然没有差别就**放弃** |

**已核实 / 不确定 / 待验证 汇总**
- **已核实**：AHE 的非加性和操作点混杂；HarnessFix 迁移后增益打折；HarnessX 没有评估较弱的 meta-agent；Self-Harness 和 SSA 的"模型特异"原话。
- **不确定**：两篇最接近工作的正文内容；同家族模型对能否调用；20 题的方差能否测出层效应。
- **待验证**：失配存在，且大于噪声；失配集中在少数几层；四种机制可以用轨迹区分；只修失配层能挽回大部分损失。
