# 候选问题：用新旧配对轨迹修升级后的回归题


## 1. 问题

模型升级后，旧 harness 在部分题上开始出错。修这些题时，把旧模型在同一道题、同一个 harness 下留下的轨迹交给诊断方，能不能修得更准、更省？如果能，好处出现在哪类题上？

## 2. 设定

| 项 | 取值 |
|---|---|
| 旧模型 M0 | Qwen3-4B-Instruct |
| 新模型 M1 | Qwen3.5-4B（本地 llama.cpp，Q4_K_M 量化） |
| harness H0 | Life-Harness 为 Qwen3-4B 演化出的 OS harness，四层全开：h2 动作校验、h3 环境（工具描述改写 + 任务解析）、h4 轨迹监控、h5 技能检索（BM25 top-1，阈值 7.5） |
| 题集 | AgentBench OS 测试集 144 题，每题最多 16 步，temperature 0 |
| 可以改的 | h3 的工具描述文本、h5 的技能条目和检索阈值、h2/h4 的规则和阈值、任一层的开关 |
| 不能改的 | 模型权重、AgentBench 的题目和判分、工具集本身（bash_action / finish_action / answer_action） |
| 推理 | 本地，无 API 费用，成本只计 rollout 次数和墙钟时间 |

选这个平台的原因：模型对是真实的同族升级；H0 是论文为 M0 演化出来的，不是我们自己写的；四层各有开关，诊断结论可以直接验证；论文报告了 M0 和 M1 在 H0 上的整体分数（Table 10：M0 0.2150→0.3960，M1 0.4236→0.4931），但没有逐题结果，逐题的新旧对比没有人看过。


## 3. 三类题

每题让 M0 和 M1 在 H0 下各跑 K=5 次，按通过率分类：

- **回归题**：M0 通过 ≥4/5，M1 通过 ≤1/5。
- **偶尔能过的题**：M1 通过 2/5 到 4/5。
- **共同失败题**：M0 和 M1 都 ≤1/5。

阈值是临时的。先跑同配置重复（A/A）测噪声底，再按噪声底定阈值。

## 4. 主张

旧轨迹只在回归题上有用。

理由：诊断最需要的材料是一条"同一题、同一个 harness 下成功了"的轨迹。把它和失败轨迹并排，差别只来自模型行为，能看出 harness 里哪条假设不再成立。这条成功轨迹从哪来：

- 偶尔能过的题：M1 自己多跑几次就有，不需要旧轨迹。
- 共同失败题：哪里都没有，旧轨迹也帮不上。
- 回归题：M1 再怎么跑也拿不到，唯一现成的成功轨迹是 M0 的，而且它在升级前的评测记录里，不用重新跑。

回归题正好是升级后要修的题。所以如果主张成立，旧轨迹恰好在最需要的地方不可替代，而且免费。

## 5. 验证项（第一步）

### 5.1 数据

| 运行 | 模型 | harness | 题数 | 次数 |
|---|---|---|---|---|
| R | Qwen3-4B | 四层全开 | 144 | 5 |
| N | Qwen3.5-4B | 四层全开 | 144 | 5 |
| N-A/A | Qwen3.5-4B | 四层全开 | 144 | 再 2 次，测噪声底 |

按上次 30 题约 25 分钟估，144 题一遍约 2 小时，共约 24 小时机器时间。先各跑 1 遍看回归题数量；如果回归题不到 10 道，换题集或模型对，不硬做。

每题记录：通过与否、步数（按唯一 tool_call id 去重）、结束用的工具、h2–h5 各自的触发记录。

### 5.2 手工诊断

从三类题各抽 5–8 道。两个人独立诊断，每人每题拿到一种信息条件，事先不知道其他人拿的是什么：

| 条件 | 诊断方拿到的材料 |
|---|---|
| A | M1 的 1 条失败轨迹 |
| B | M1 的 5 条轨迹（多次采样） |
| C | B 的材料 + M0 的 5 条轨迹 |

条件 B 的作用：把"多了一条轨迹可以对照"和"这条轨迹来自旧模型"分开。如果 C 不比 B 好，旧轨迹就没有独立价值。

诊断输出固定为两项：
1. H0 里负责的部分，粒度到具体条目。例如：h3 对 finish_action 的描述；h5 某一条技能；h2 的重复命令阻断规则；h4 的步数预算。
2. 一条具体改法：改文本、删条目、调阈值、关掉某层，或限定只对 M0 生效。

同时记录每题用的时间和读过的轨迹条数。

### 5.3 打分

不靠评审。按诊断给出的改法改 H0，让 M1 在这道题上重跑 5 次：

- 通过率升到噪声底以上：诊断正确。
- 没变化：诊断错误。

另外在 10 道 M1 原本能过的题上重跑一次，记录改法有没有带来副作用。

### 5.4 判据

| 结果 | 决定 |
|---|---|
| 只在回归题上，C 的正确率明显高于 B；另两类题上 C 与 B 无差别 | 主张成立，进入第 6 节的流程实验 |
| 三类题上 C 与 B 都无差别 | 旧轨迹档案不值得建，这条线放弃 |
| 所有题上 C 都更好 | 机制不是"缺成功轨迹"，重新分析好处从哪来，再决定 |

## 6. 主张成立后的流程

只修回归题，诊断用配对轨迹，预算花在验证上。

| 步 | 输入 | 动作 | 输出 | 成本 |
|---|---|---|---|---|
| 0 | 升级前评测记录 | 无 | M0 在 H0 上的逐题结果和轨迹 | 0，本来就有 |
| 1 | M1、H0、题集 | M1 每题跑 K 次 | 回归题集合 | 144 × K 次 rollout。任何做法都要付，不跑就不知道有没有回归 |
| 2 | 每道回归题的 M1 失败轨迹 + M0 成功轨迹 | 固定的 LLM 和 prompt 做诊断 | 负责的条目 + 改法 | 每题 1 次 LLM 调用，无 rollout |
| 3 | 各题诊断 | 按条目归并 | 少量补丁候选，各带对应的回归题 | 0 |
| 4 | 每个补丁 | 单独施加；M1 在对应回归题和一组对照题上各跑 K 次；若 H0 仍服务 M0，M0 也跑 | 接受或拒绝 | 补丁数 × (回归题 + 对照题) × K，主要开销 |
| 5 | 以上记录 | 分三项记账 | 诊断：LLM 调用数、读的轨迹数；搜索：补丁候选数；验证：rollout 数 | — |

接受条件：回归题恢复超过噪声底；对照题没有超出噪声底的下降；M0 不变差。

"快"的定义：达到"恢复 X% 回归题且通过非回归检查"所需的 M1 rollout 数。

## 7. 对照

| 臂 | 做法 | 回答的问题 |
|---|---|---|
| 冻结 | H0 不改 | 下界 |
| 去 harness | M1 不用 H0 | 零成本的真实候选；上次 pilot 里无 harness 分数更高 |
| 整体重演化 | Life-Harness 演化器在 M1 上重跑，验证 rollout 数与我们对齐 | 现有方法直接用是否就够 |
| 只看 M1 | 同一流程，第 2 步不给 M0 轨迹，给 M1 多采样 | 旧轨迹的独立贡献，核心对照 |
| 等预算采样 | 测试时并行采样 | 改 harness 是否只是多采样的效果 |

成立判据：我们的臂在回归恢复上优于"只看 M1"；在同等验证预算下不低于"整体重演化"；同时通过两个模型的非回归检查。

## 8. 最简单的替代做法

1. 冻结不动。StarHarness 显示同族升级后冻结的 harness 在三个基准上仍然为正，只是增益缩小。这个基线不弱。
2. 去掉 harness。零成本。
3. 在 M1 上从零重建。ASDA 的 warm-up 级重蒸馏不到 $12 就得到 +5.00。
4. 直接照搬厂商迁移指南，不跑 rollout。

写不出优于这四项的理由，候选就该淘汰。目前能写的理由只有一条：以上四项都不做逐题诊断，也都不检查对 M0 的副作用。这条理由要靠第 7 节的实验兑现。

## 9. 最强反例

1. **成功轨迹可能不是关键。** SKILL-KD 里 39.2% 被接受的 patch 来自 teacher 失败的轨迹；LiveMath 上 teacher 几乎全错，提升仍然很大。增益可能主要来自重跑验证，不是对比本身。如果这样，第 4 节的机制不成立，验证项会得到"三类题无差别"或"所有题都更好"。
2. **同族模型差别太小。** CONTRAMEM 的 +7.5 来自三家不同厂商的模型；同模型多采样对比只有 +1.7。同族新旧模型的行为更接近，增益可能更接近后者。
3. **回归题太少。** What Aggregate Scores Miss 中可靠回归的题占 4.4–15%。144 题上可能只有 7–20 道，统计功效不够。
4. **自动诊断方用不好配对轨迹。** 手工验证成立，不代表 LLM 诊断方也成立。第 6 节第 2 步可能需要专门设计 prompt，这本身是一个风险。
5. **等预算采样可能更好。** Rethinking 在 Terminal-Bench 上发现等 rollout 预算的并行采样优于改 harness。hotfix 是一次性开销，采样是每次查询的开销，记账方式要先定下来，否则这个对照做不公平。

## 10. 已知的相关工作

- 同族升级 + 冻结 harness 给了数字的：StarHarness（增益缩小但为正）、ASDA（skill 迁移 −2.33）、Life-Harness（4B 级为正）。都没有逐题结果，没有新旧轨迹对比。
- 做过新旧轨迹对比的：SKILL-KD（一次性对比 59.0 不优于只看失败 60.1；加重跑验证后 66.8 vs 62.1）、CONTRAMEM（跨厂商对比 +7.5，同模型多采样 +1.7）。方向都是强→弱或跨厂商，不是同族旧→新。
- 做过跨模型逐题分析的：What Aggregate Scores Miss（无 harness）、Co-Evolving（模型轴是 LoRA，不是版本）。

## 11. 还不知道的

- 主张是否成立。这是前提。
- 回归题的数量，以及 A/A 噪声底的大小。决定验证项有没有统计功效。
- 自动诊断方能不能复现手工结果。
- 整体重演化在同等预算下的表现。如果它也赢，结论是 hotfix 没有优势，这是一个否定结果。
